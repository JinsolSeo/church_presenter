# Church Presenter 사용자 안내

## 안전한 시작

앱은 언제나 두 Live 채널을 BLACK으로 시작하며 프로그램 실행 직후 전체화면을
열지 않습니다. 먼저 `화면 / 오디오 설정`에서 Controller, Broadcast, Venue 역할과
공통 오디오 출력 장치를 지정하십시오. 물리 화면이 부족하면 Simulation Mode를 선택합니다.
설정을 확인한 뒤에만 `출력 시작`을 누릅니다.

출력 창이 닫힌 상태에서 TAKE 또는 TAKE BOTH를 누르면 지정된 출력 창을 자동으로
시작한 뒤 Live를 반영합니다. 화면 할당 오류 등으로 출력 창을 시작할 수 없으면
TAKE는 실패하고 기존 Live를 유지합니다. macOS의 물리 출력은 별도 Space로 전환되는
네이티브 전체화면 대신, 지정 모니터 전체를 덮는 테두리 없는 출력 창을 사용합니다.

Preview는 다음 콘텐츠를 준비하는 영역이고 Live는 현재 실제 출력입니다. 카드나
페이지 선택은 Preview만 바꿉니다. 각 콘텐츠 탭의 TAKE 또는 중앙의 빨간 TAKE BOTH를
실행해야 Live가 변경됩니다. TAKE BOTH는 두 Preview가 모두 준비됐을 때만 함께
적용됩니다.

Controller 상단의 Preview/Live 미러는 16:9 비율을 유지합니다. 상단 모니터 영역과
하단 콘텐츠 탭 사이의 구분선을 끌어 운영 환경에 맞게 높이를 조절할 수 있고, 이
비율은 다음 실행에 복원됩니다. 기본값은 상단 모니터에 약 60%를 배정합니다. 하단
패널 자체는 배정된 높이에 맞게 압축되므로 하단 전체를 감싸는 바깥 스크롤바가
생기지 않습니다. 긴 자막 카드나 파일 목록처럼 실제 데이터가 넘치는 목록만 해당
목록 안에서 스크롤되며, 상단 모니터가 지나치게 작아지거나 Controller 전체가 세로로
밀려나지 않습니다.

작업 결과와 오류는 창 맨 아래 상태줄에 표시됩니다. 저장된 창 크기가 현재 화면보다
크면 사용 가능한 화면 영역 안으로 자동 조정됩니다. 기본 Controller 설계 기준은
FHD(1920×1080)이고 기본 창 크기는 1600×900입니다. 너비가 1440px 미만이거나 높이가
900px 이하이면 별도 설정 없이 컴팩트 밀도가 자동 적용되어 글꼴, 버튼, 여백, PDF
썸네일과 영상 패널의 크기를 줄입니다. 예배 순서 Dock은 창 크기에 따라 자동으로
숨겨지거나 분리되지 않으며 항상 표시됩니다. 닫을 수는 없지만 좌우 이동이나 floating은
가능합니다. 최소 지원 크기는
800×600이고, 1100px보다 좁으면 상단 도구 영역도 여러 줄로 재배치됩니다. 제품명 옆에는
작은 제작자 표기 `by Jinsol`이 표시됩니다.

## 화면 테마

상단 `테마` 선택기에서 Light Professional, Dark Modern, Minimalist Light,
Warm Linen, Deep Ocean, Graphite Violet를 즉시 전환할 수 있습니다. 선택한 테마는
사용자 설정에 저장되고 다음 실행에 복원됩니다.
테마는 Controller, 설정 대화상자, Simulation 창의 제어 UI에 적용되지만 자막 Key
Color, PDF, 영상 및 실제 Broadcast/Venue 출력 콘텐츠를 변경하지 않습니다.

Preview는 파란 계열의 헤더와 `PREVIEW` 문구로, Live는 빨간 계열 헤더와 `LIVE`
문구로 구분합니다. 영상 탭은 단일 Preview Cue와 TAKE를 기본 버튼으로 표시하고,
`양쪽 Cue`와 `TAKE BOTH`만 각각 파란색과 빨간색으로 강조합니다. 다른 콘텐츠의
Live 전환 버튼과 삭제 버튼의 위험 동작 스타일도 서로 구분합니다. 저장된 테마 파일이
없거나 올바르지 않으면 Light Professional로 복구하고 상태줄에 비치명적 경고를
표시합니다.

모든 테마의 자막 출력 카드에서는 Live와 현재 Preview만 각각 빨간색·파란색 계열의
테마 배경으로 강조합니다. 카드 접두사도 `LIVE`와 `PREVIEW`만 표시하며, 나머지
카드는 상태 접두사와 별도 배경 없이 테마 기본 글자색으로 표시합니다.

## 원격 연결

이전의 상단 `예배 순서` 버튼 자리에는 `원격 연결` 버튼이 있습니다.

1. 노트북과 태블릿 또는 스마트폰을 같은 Wi-Fi에 연결합니다.
2. Church Presenter 상단의 `원격 연결`을 누릅니다.
3. 여러 로컬 IP가 표시되면 원격 기기와 같은 네트워크의 주소를 선택하고 필요하면
   `서버 재시작`을 누릅니다.
4. 표시된 QR 코드를 iPad Safari 또는 Android Chrome으로 스캔합니다.
5. 브라우저의 미러링 화면을 탭·드래그·스크롤하거나 하드웨어/화면 키보드로
   Controller를 조작합니다.

모바일 터치 조작은 다음과 같습니다.

- 한 손가락 탭과 드래그는 Controller의 클릭과 드래그로 전달됩니다.
- 두 손가락을 벌리거나 오므리면 화면 맞춤 배율부터 최대 4배까지 원격 화면만
  확대·축소됩니다. 두 손가락을 같은 방향으로 움직이면 확대 화면을 이동합니다.
- 두 손가락 동작은 Controller 입력으로 전달되지 않으며, pinch 직후 브라우저가
  만드는 추가 클릭도 무시됩니다.
- 화면을 빠르게 두 번 탭하면 탭 위치를 중심으로 2배 확대되고, 확대 상태에서 다시
  두 번 탭하면 화면 맞춤으로 돌아갑니다.
- 상단 `화면 맞춤`은 현재 확대와 이동을 모두 초기화합니다. 화면 회전, 브라우저
  크기 변경, 전체 화면 전환 후에도 현재 확대 배율과 화면 중심이 유지됩니다.

iPad에서 조작 직후 화면 반영이 느리더라도 탭을 반복하지 마십시오. 브라우저는
디코딩이 느릴 때 중간 미러링 프레임을 자동으로 버리고 최신 화면부터 표시합니다.
이 동작은 클릭 전송을 제한하지 않으므로 Controller에는 입력이 먼저 도착합니다.

기본 포트는 8765이며 이미 사용 중이면 8790까지 자동으로 다음 빈 포트를 찾습니다.
여러 기기가 같은 QR 코드로 동시에 접속할 수 있고 다이얼로그의 `접속 기기` 수에
반영됩니다. 다이얼로그를 닫아도 서버는 유지되며 `원격 연결`을 다시 누르면 같은
주소와 상태를 확인할 수 있습니다. `주소 복사`는 QR과 동일한 URL을 복사합니다.
`연결 종료`는 모든 브라우저 연결을 닫고 URL 토큰을 즉시 폐기합니다. 재시작하면
새 토큰이 만들어지므로 이전 URL은 다시 사용할 수 없습니다.

접속 URL에는 충분히 긴 일회성 난수 토큰이 포함됩니다. 서버는 인증되지 않은 HTTP와
WebSocket 요청을 거부하며 화면·입력 이외의 파일 읽기, 업로드, 셸 실행 API를
제공하지 않습니다. 서버는 노트북 내부에서만 실행되고 외부 인터넷, 클라우드,
UPnP 포트 포워딩을 사용하지 않습니다.

연결되지 않으면 다음을 확인하십시오.

- Windows 첫 실행 방화벽 창에서 사설 네트워크 접근을 허용합니다. 수동으로는
  `Windows 보안 > 방화벽 및 네트워크 보호 > 방화벽을 통해 앱 허용`에서 Church
  Presenter 또는 패키징에 사용한 Python 실행 파일을 허용합니다.
- macOS는 `시스템 설정 > 네트워크 > 방화벽 > 옵션`에서 Church Presenter의 수신
  연결을 허용합니다.
- 게스트 Wi-Fi, AP isolation/client isolation, 호텔·사내망의 단말 간 통신 차단은
  같은 Wi-Fi 이름을 사용하더라도 연결을 막습니다.

미러링은 Controller와 Qt 애플리케이션 안에서 열린 일반 다이얼로그를 대상으로
합니다. 원격 연결 QR 다이얼로그 자체와 운영체제 네이티브 파일 선택창은 전송하지
않습니다. 브라우저의 `전체 화면`, `화면 맞춤`, `키보드` 버튼은 접속 조작만
보조하며 앱 기능을 별도의 HTML UI로 복제하지 않습니다. 영상 재생 중에는 Windows
하드웨어 디코더의 GPU 프레임 변환으로 Controller 조작이 느려지지 않도록 영상 영역만
준비된 첫 프레임과 `원격은 정지 화면` 안내로 표시합니다. 재생 버튼, 위치, 목록과
나머지 Controller 화면은 계속 갱신되며 노트북과 실제 출력 영상은 정상 재생됩니다.

### Windows/macOS 수동 검증

두 운영체제에서 각각 Controller를 실행해 예배 순서 패널과 원격 버튼을 확인한 뒤
같은 Wi-Fi의 Safari/Chrome에서 QR로 접속합니다. 자막/PDF 선택, 이전·다음, TAKE,
TAKE BOTH, 영상/배경음악의 재생·slider·scroll, 화면 회전, 두 기기 동시 접속을
검증합니다. Wi-Fi를 끊었다 연결해 브라우저의 점진적 재연결을 확인하고,
`연결 종료` 후 이전 URL 거부와 서버 실행 중 앱 종료가 멈추지 않는지 확인합니다.
실제 출력은 종료 시 양쪽 모두 BLACK으로 바뀌어야 합니다.

iPad Safari와 Android Chrome에서는 한 손가락 탭·드래그, 1~4배 pinch, 확대 상태의
두 손가락 이동, 더블 탭 전환, `화면 맞춤`, 세로/가로 회전, 전체 화면 전환을 각각
확인합니다. pinch 중 노트북 Controller가 반응하지 않고 pinch 종료 직후에도
의도하지 않은 클릭이 발생하지 않아야 합니다. 확대된 화면의 네 모서리와 중앙을
탭해 실제 Controller의 같은 위치가 눌리는지도 확인합니다.

## 자막과 PDF 동시 진행

Controller 중앙의 `자막 + PDF 동시 진행` 영역에 포커스를 두면 두 Preview에 현재
올라간 콘텐츠 종류를 기준으로 다음 키를 함께 처리합니다. Broadcast Preview가
자막이고 Venue Preview가 PDF라면 각각 다음 자막과 다음 PDF를 준비합니다. 한쪽에만
자막 또는 PDF가 있다면 해당 Preview만 이동합니다.

`함께 이전`, `함께 다음`, `TAKE BOTH` 버튼을 누르면 동시 진행
모드가 꺼져 있어도 자동으로 켜진 뒤 동작합니다. 이동 후 상태줄에는 현재 자막
카드와 PDF 순서 위치가 표시됩니다.

```text
Left / Right   자막 카드와 PDF 페이지를 함께 이전/다음으로 이동
Home / End     자막과 PDF를 각각 처음/마지막으로 이동
Enter          Broadcast 자막과 Venue PDF를 TAKE BOTH
```

중앙 체크박스와 버튼 중 하나를 클릭하면 동시 진행 영역에 포커스가 생기며 굵은
테두리로 표시됩니다. `연동 제어` 제목 아래 체크박스는 하나의 indicator와 `동시 진행`
문구로 상태를 표시합니다.
동시 진행이 켜져 있더라도 자막 탭이나 PDF 탭을 클릭해 포커스를 옮기면 방향키와
Enter는 해당 탭에만 적용됩니다.

`바로 Live`를 체크하면 동시 진행 영역에 포커스가 있을 때 Left/Up/PageUp은 함께
이전, Right/Down/PageDown은 함께 다음으로 이동한 뒤 TAKE BOTH까지 자동 실행합니다.
`함께 이전`과 `함께 다음` 버튼도 같은 방식으로 동작합니다. PDF 고해상도 렌더가
필요하면 내부 Preview 준비가 끝날 때까지 기다렸다가 자동 TAKE하므로, 운영자는 별도
TAKE 버튼을 누르지 않아도 됩니다. 준비 실패, 체크 해제 또는 다른 콘텐츠 선택 시
자동 TAKE 예약을 취소하고 기존 양쪽 Live를 유지합니다. 이 체크 상태는 다음 실행에
복원됩니다.

PDF 고해상도 Preview가 아직 준비되지 않았으면 Enter를 눌러도 기존 양쪽 Live가
유지됩니다. 텍스트 입력 필드에 포커스가 있을 때는 방향키를 가로채지 않으며,
자막 원본 편집 필드의 Enter는 문장 수정만 확정하고 TAKE로 전달되지 않습니다.

## 자막

`TXT 열기`로 UTF-8 또는 UTF-8-SIG 파일을 엽니다. 한 개의 비어 있지 않은 원본
줄이 한 자막이며 빈 줄은 읽을 때 제외됩니다. `그룹 n`은 원본을 바꾸지 않고
연속 n줄로 출력 카드를 다시 계산합니다. 왼쪽에서 카드를 고르고 오른쪽에서 그
카드의 원본 줄을 선택해 편집합니다. 추가, 삭제, 위/아래 이동은 메모리에서만
수행되며 `저장` 전에는 원본 파일이 바뀌지 않습니다. 저장은 UTF-8(BOM 없음),
LF 줄바꿈, 빈 줄 제외 정책입니다.

`줄 추가`는 현재 선택한 원본 문장의 바로 위에 `새 자막`을 삽입하고 편집 필드에
포커스를 둡니다. 추가·삭제·위로·아래로 버튼은 원본 편집 영역 아래 한 줄에 표시됩니다.
`다시 불러오기`는 현재 TXT 파일의 디스크 내용을 다시 읽습니다. 미저장 변경이 있을 때
표시되는 저장 확인에서 `예`는 먼저 저장하고, `아니요`는 변경을 버린 뒤 계속 열며,
`취소`만 파일 열기 또는 다시 불러오기를 중단합니다.

자막 탭에서 Left/Right, Home/End로 Preview를 이동하고 Enter로 Broadcast TAKE를
실행합니다. 단, 원본 한 줄 편집 필드의 Enter는 수정만 확정하며 동시 진행의 활성화
여부와 관계없이 Broadcast TAKE 또는 TAKE BOTH를 실행하지 않습니다.

`Subtitle Style Settings`는 모든 스타일 항목과 세 기본 프리셋을 제공합니다.
대화상자의 Preview 적용은 대화상자 내부 미리보기만 바꾸며, 확인 후 현재
Broadcast Preview에만 적용됩니다. 기존 Live 스타일은 다음 TAKE까지 유지됩니다.

## PDF

`PDF 폴더`로 라이브러리를 지정합니다. 목록은 운영 중 순서가 바뀌지 않도록 파일명
내림차순으로 고정되며, PDF 파일을 패널에 끌어 놓을 수도 있습니다. 폴더·새로고침·
Preview 대상 체크박스는 왼쪽 파일 목록과 함께 배치됩니다. 폴더 검색, 문서
검증, 페이지 렌더링은 백그라운드에서 처리되고 손상된 PDF에는 경고가 표시됩니다.
왼쪽 PDF 파일 목록은 최소 300px 폭을 유지합니다.

페이지 썸네일은 원본 PDF 페이지 번호 오름차순으로 고정됩니다. 드래그 이동은
지원하지 않으며 과거 설정에 저장된 사용자 순서도 적용하지 않습니다. Left/Right 및
함께 이동 버튼은 이 숫자 순서를 따릅니다. 페이지 번호와 `페이지 이동` 버튼은
썸네일 아래에서 TAKE 버튼과 같은 작업 행에 표시됩니다.

기본 대상은 체크된 `Venue Preview`입니다. `Broadcast Preview`와 `Venue Preview` 중
하나를 선택하면 해당 채널만 준비하고, 두 체크박스를 모두 선택하면 이후 페이지마다
두 Preview를 함께 준비합니다. 두 채널 선택 모드에서는 TAKE BOTH로 송출하며 중앙
`동시 진행` 모드는 자동으로 해제됩니다. PDF는 자르지 않고 원본 종횡비를 유지하며
남는 영역을 검게 표시합니다.

## 빈 화면

`빈 화면` 탭에서는 검정, 크로마키 그린(`#00FF00`), 크로마키 블루(`#0000FF`) 중
하나를 오른쪽의 컴팩트 프리셋 영역에서 고릅니다. 색상 프리셋을 선택하는 것만으로는
Preview나 Live가 바뀌지 않습니다. `송출 Preview 준비`, `현장 Preview 준비` 또는
`Send to Both`로 먼저 Preview에 올린 뒤 해당 TAKE 버튼을 눌러야 실제 출력됩니다.

검정은 시작·종료·장치 분리 시 사용하는 기존 안전 BLACK 상태입니다. 크로마키
프리셋은 자막이 없는 단색 전체 화면으로 출력되며, 외부 키어에서 녹색 또는 파란색
빈 Key Feed가 필요할 때 사용할 수 있습니다. 빈 화면 색상은 예배 순서 Preview
프리셋에도 함께 저장됩니다.

## 예배 순서 Preview 프리셋

Controller 오른쪽의 `예배 순서` 패널은 현재 Broadcast Preview와 Venue Preview를
한 쌍으로 저장합니다. 두 Preview를 먼저 원하는 자막, PDF, 영상, 검정 또는 크로마키
빈 화면으로 준비하고 이름을 입력한 뒤 `현재 Preview 저장`을 누르십시오. 같은 이름으로 다시
저장하면 기존 프리셋을 현재 Preview 내용으로 덮어씁니다.
패널 제목 아래에는 설명문 대신 현재 작업 중인 JSON 파일 이름만 표시됩니다.

저장된 프리셋은 위에서 아래로 예배 진행 순서에 맞춰 표시됩니다. `▲`와 `▼`로
순서를 바꾸고, `저장`, `이름 변경`, `삭제`로 목록을 관리할 수 있습니다. 항목의 큰
버튼을 눌러 Preview를 준비한 뒤 이번 예배에 맞게 자막 카드나 PDF 페이지를 조정하고
그 항목의 `저장`을 누르면 이름과 순서는 유지한 채 현재 Broadcast/Venue Preview
위치로 덮어씁니다. 이 항목별 `저장`은 현재 실행 중인 작업 목록에만 임시로 반영되며
불러온 외부 JSON 파일을 변경하지 않습니다.

`다른 이름`으로 현재 전체 예배 순서와 프리셋 순서를 새 JSON 파일로 저장할 수
있습니다. `파일 열기`로 저장된 예배 순서를 불러오면 현재 작업 목록을 교체하지만,
행별 `저장`을 포함한 이후 수정은 불러온 원본 JSON을 변경하지 않는 임시 작업입니다.
조정을 마친 뒤 `다른 이름`을 눌러야 수정된 작업 목록이 새 JSON에 기록됩니다.
마지막으로 연 파일은 다음 실행 때 자동으로 다시 열고, 파일이 사라졌다면 App Data의
안전 복사본으로 시작합니다.

예배 순서 JSON에는 실제 TXT/PDF/영상 파일 경로나 자막 문구를 저장하지 않습니다.
자막은 카드 번호, PDF는 페이지 번호, 영상은 콘텐츠 종류만 저장합니다. 따라서 매주
다른 자막과 PDF를 먼저 불러온 뒤 같은 예배 순서 파일을 열어 사용할 수 있습니다.
프리셋 버튼을 누르면 저장된 번호를 현재 자막 문서와 현재 선택한 PDF에 적용합니다.
현재 파일에 해당 카드나 페이지가 없으면 두 Preview를 변경하지 않고 오류를 표시하므로,
파일을 불러온 뒤 프리셋 번호를 이번 예배에 맞게 덮어써 조정할 수 있습니다.

프리셋의 큰 이름 버튼을 누르면 두 Preview만 바뀌며 Live는 유지됩니다. PDF와 영상은
고해상도 렌더링 또는 첫 프레임 Cue가 끝날 때까지 중앙 동시 진행 영역의 `TAKE BOTH`가
비활성화됩니다. 프리셋 적용 후 키보드 포커스도 이 영역으로 자동 이동하므로 Enter로
TAKE BOTH를 실행할 수 있습니다. 두 Preview를 확인하고 전환하면 기존 원자적 규칙에
따라 양쪽 Live가 함께 갱신됩니다. 저장된 PDF나 영상 파일이 이동·삭제된 경우
프리셋을 적용하지 않고 기존 Preview와 Live를 모두 유지합니다.

## 화면 분리와 종료

Live 중 물리 화면이 분리되면 해당 채널은 BLACK으로 바뀌고 경고가 표시되며 앱은
계속 실행됩니다. 재연결 후 화면을 다시 지정하고 수동으로 출력하십시오. 종료 시
미저장 자막을 확인하고 두 출력 모두 BLACK으로 칠한 후 출력 창을 닫고 설정을
저장합니다.

## 영상

`영상` 탭의 파일은 수정 날짜를 기준으로 최신 파일이 항상 맨 위에 표시되며, 목록
검색은 백그라운드에서 실행됩니다. 파일을 클릭하면 재생 대상만 선택되며 Preview는
바뀌지 않습니다. 송출 또는 현장 채널을 확인한 뒤 `Preview Cue`를 누르면 LOADING을
거쳐 실제 첫 프레임 CUE가 됩니다. 이때 Live와 배경음악은 바뀌지 않습니다.
상단 파일 도구는 왼쪽부터 영상 폴더와 경로가 표시되고, 새로고침은 왼쪽 파일
패널의 오른쪽 끝에 배치됩니다. 송출/현장 선택은 오른쪽 제어 패널 위에 표시됩니다.
오른쪽 제어 패널 상단에는 Preview Cue, 양쪽 Cue, TAKE, TAKE BOTH가 같은 크기의
2×2 버튼으로 배치되며, 영상 재생·탐색·볼륨 제어는 그 아래에 표시됩니다.

```text
파일 선택 → Preview Cue 버튼 → TAKE → Live Cue → 재생
```

Broadcast 또는 Venue를 명확히 선택한 뒤 TAKE 하십시오. TAKE 후에도 첫 프레임에서
멈추며 `재생`을 눌러야 영상과 영상 오디오가 시작됩니다. `양쪽 Cue`는 두
Preview를 모두 준비하고 TAKE BOTH는 양쪽 준비가 성공했을 때만 원자적으로 적용합니다.
TAKE BOTH로 같은 영상을 올린 뒤 `재생`을 누르면 Broadcast와 Venue가 모두 재생됩니다.
일시정지, 정지, 처음으로, 탐색도 양쪽에 함께 적용되며 한쪽을 개별 TAKE하면 연동이
자동으로 해제됩니다. 동일 오디오가 겹치지 않도록 양쪽 연동 중에는 Broadcast 영상의
오디오는 `화면 / 오디오 설정`에서 선택한 공통 출력 장치로 재생됩니다. `시스템 기본
출력`을 선택하면 macOS 또는 Windows의 현재 기본 장치를 따릅니다. USB, HDMI,
3.5mm 및 Bluetooth 장치가 Qt에서 감지되면 목록에서 명시적으로 선택할 수도 있습니다.
선택한 장치가 분리되면 앱은 시스템 기본 출력으로 전환하고 상태줄에 경고합니다.
같은 영상을 다시 선택해도 0초의 첫 프레임으로 새로 Cue됩니다. PDF나 BLACK을
Preview로 선택하면 이전 영상의 TAKE 준비 상태는 자동으로 해제됩니다.

재생/일시정지, 정지, 처음으로, 탐색, 볼륨, 음소거를 사용할 수 있습니다. 정지와 자연
종료 및 치명적 재생 오류는 해당 Live만 BLACK으로 전환합니다. BLACK/PDF/VIDEO 간
전환 Fade는 안정적인 운영을 위해 250ms로 고정되며 영상 탭에는 별도 설정을 표시하지
않습니다. 영상이 해당 채널의
Live가 아닐 때는 영상 재생 제어가 비활성화되어 다른 Live를 잘못 BLACK으로 바꾸지
않습니다.

영상 탭에 포커스가 있고 입력 위젯을 편집하지 않을 때 Enter는 선택 채널 TAKE,
Space는 Play/Pause, S는 Stop, Home은 처음으로 이동입니다. 영상 목록의 Left/Right는
파일 선택을 이동합니다. 탐색 슬라이더에 포커스가 있으면 키를 가로채지 않습니다.

## 배경음악

`음악 폴더`로 지정한 폴더가 곧 재생목록입니다. 지원 오디오 파일을 파일명 또는 수정
날짜 순으로 스캔해 왼쪽 목록에 표시하고, 오른쪽 컴팩트 플레이어에서 선택 곡 재생,
재생/일시정지/정지, 이전/다음, 탐색, 볼륨, 음소거와 반복 없음/한 곡/전체 반복을
제어합니다. 재생 버튼은 `⏮`, `▶`, `⏸`, `■`, `⏭` 기호로 표시되며 툴팁과 접근성
이름에는 전체 동작명이 제공됩니다. 3초 이상 재생한 뒤 이전 곡을 누르면 현재 곡의
처음으로 돌아갑니다. 현재 Cue·재생·일시정지·버퍼링 중인 곡은 왼쪽 목록에서 테마의
파란 accent 색으로 강조됩니다. 오른쪽 플레이어에는 현재 곡과 재생 상태를 고정 표시하고,
상세 진행 결과와 오류 안내는 애플리케이션 하단 상태바에 표시합니다.

`YouTube URL 추가`에는 공개된 단일 영상 URL을 입력합니다. URL은 별도 파일명을 묻지
않고 현재 음악 폴더의 `youtube_url.json`에 즉시 원자적으로 저장됩니다. 이 파일이 없는
폴더에서는 YouTube 항목을 불러오지 않습니다. URL을 삭제하거나 fallback을 변경해도
같은 파일이 자동 갱신됩니다. 제목과 재생 시간은 백그라운드에서 조회되며 조회 중·사용
가능·오류 상태가 폴더 재생목록에 표시됩니다.

YouTube 항목을 선택하고 `대체 파일 지정`으로 운영 PC의 로컬 음악을 연결해
두는 것을 권장합니다. 스트림 해석, 네트워크 또는 재생이 실패하면 fallback 사용
문구를 표시한 뒤 로컬 파일로 전환합니다. `상태 다시 확인`은 실패한 메타데이터를
다시 조회합니다. libmpv/yt-dlp가 없을 때는 YouTube 항목만 오류가 되고 로컬 음악과
영상은 계속 사용할 수 있습니다. YouTube 오디오도 `화면 / 오디오 설정`의 공통 출력
장치를 사용하며, 장치 이름을 libmpv에 대응할 수 없는 경우 시스템 기본 출력으로
전환합니다.

별도 재생목록 저장·다른 이름으로 저장·불러오기는 사용하지 않습니다. 폴더에서 삭제된
로컬 파일은 새로고침 시 목록에서도 제거됩니다. 실행을 다시 시작해도 영상이나 음악을
자동 재생하지 않습니다. 재생 가능한 YouTube
스트림 URL은 매번 다시 해석하며 JSON에 저장하거나 파일로 다운로드하지 않습니다.
비공개·연령 제한·로그인 필요 영상과 YouTube playlist 전체 가져오기는 지원하지
않습니다. 외부 서비스 변경과 네트워크 상태에 따라 실패할 수 있으며 이용 조건과
콘텐츠 권리는 사용자가 확인해야 합니다.

실제 영상 Play가 시작되는 순간에만 재생 중인 배경음악이 자동 Pause됩니다. 영상
Preview, TAKE, Pause, Stop, 종료는 음악을 자동으로 변경하거나 재개하지 않습니다.
음악 탭의 Space는 Play/Pause, macOS Command+Left/Right 또는 Windows
Ctrl+Left/Right는 이전/다음 곡입니다.
